# الأمان وتأمين الاتصال بين الموقع والداتا سنتر

## 1. نموذج الاتصال: لا منافذ واردة في الداتا سنتر

```
 [هاتف/كمبيوتر] ──HTTPS──▶ [الخادم السحابي :443] ◀──WSS (صادر)── [Audio Agent في الداتا سنتر]
```

- جهاز التشغيل **يبدأ** الاتصال نحو الخادم. لا تحتاج إلى Port Forwarding أو فتح أي منفذ وارد على جدار الحماية.
- القاعدة الوحيدة المطلوبة في جدار حماية المؤسسة: السماح لجهاز التشغيل بالخروج إلى `audio.example.com:443` (TCP). يُفضَّل تقييدها بعنوان IP الخادم.
- الأوامر تصل للجهاز عبر نفس الاتصال الصادر المفتوح (WebSocket)، وتأكيد التنفيذ يعود عبره.

### خيارات لشبكات أكثر تشددًا
| الخيار | متى |
|---|---|
| **الافتراضي**: WSS صادر عبر 443 | يكفي لمعظم المؤسسات |
| وكيل HTTP مؤسسي | Python تحترم `HTTPS_PROXY` تلقائيًا |
| شهادة CA داخلية | ضع `tls_verify = "C:/certs/corp-ca.pem"` في إعدادات الجهاز |
| الخادم داخل الشبكة (بدون سحابة) + VPN للوصول الخارجي | إن كانت السياسة تمنع أي خروج للإنترنت: انشر Docker Compose على خادم داخلي واتصل من الخارج عبر VPN المؤسسة (WireGuard/IPsec) أو Cloudflare Tunnel / Tailscale |
| mTLS بين Caddy والجهاز | ممكن إضافته في Caddy (`client_auth`) كطبقة ثانية فوق رمز الجهاز |

## 2. ضوابط مطبّقة في الكود

| الطبقة | الضابط |
|---|---|
| النقل | HTTPS إلزامي (Caddy + Let's Encrypt)، HSTS، `upgrade-insecure-requests` |
| تسجيل الدخول | bcrypt (12 جولة)، رسالة خطأ موحّدة، وقت استجابة موحّد لاسم مستخدم غير موجود، **قفل الحساب 15 دقيقة بعد 5 محاولات**، حد 10 محاولات/دقيقة لكل IP |
| الجلسات | رمز عشوائي 256-bit يُخزَّن مُجزّأً (SHA-256) في قاعدة البيانات، كوكي `HttpOnly; Secure; SameSite=Strict` باسم `__Host-` في الإنتاج، انتهاء 12 ساعة مع تجديد عند الاستخدام، إلغاء فوري عند الخروج/تغيير الدور/التعطيل/تغيير كلمة المرور |
| كلمات المرور | 10 أحرف على الأقل مع حروف وأرقام، كلمة مرور مؤقتة إجبارية التغيير عند إنشاء مستخدم |
| CSRF | SameSite=Strict + رفض أي طلب تعديل بـ `Origin` مختلف |
| الصلاحيات | فحص الدور في **كل** مسار API على الخادم (الواجهة تخفي الأزرار فقط للراحة) + قيود ثانية داخل الجهاز (`privileged`, `maxVolume`) |
| رموز الأجهزة | `rec_<8 hex>_<43 chars>` (256-bit)، تُعرض مرة واحدة وتُخزَّن مُجزّأة؛ **الإلغاء يقطع الاتصال فورًا** ويمنع إعادة الاتصال؛ تدوير الرمز يُبطل القديم |
| رفع الملفات | التحقق من نوع الملف من محتواه (RIFF/WAVE، ID3/MPEG) لا من امتداده، حد الحجم، اسم تخزين عشوائي (UUID) لا يعتمد على اسم المستخدم، قراءة المدة للتأكد من سلامة الملف |
| الأوامر | تحقق zod صارم، مهلة صلاحية، idempotency |
| واجهة API | Helmet/CSP، حد عام 600 طلب/دقيقة، رسائل خطأ لا تكشف تفاصيل داخلية |
| السجلات | `AuditLog` لكل عملية مستخدم (دخول، فشل دخول، قفل، رفع، حذف، أوامر، تعديل إعدادات، أجهزة) مع IP؛ إخفاء الكوكيز وترويسات المصادقة من سجلات الخادم |
| قاعدة البيانات | على شبكة Docker داخلية غير مكشوفة، نسخ احتياطي يومي |
| الجهاز المحلي | ملف الإعدادات (يحوي الرمز) بصلاحيات 600 (Linux) أو ACL للمسؤولين فقط (Windows)، واجهة الصحة المحلية على `127.0.0.1` فقط |

## 3. توصيات تشغيلية
1. غيّر كلمة مرور مدير النظام الأولى فورًا، وأنشئ حسابًا مستقلًا لكل شخص (لا حسابات مشتركة).
2. امنح `AUDIO_MANAGER` لمن يشغّل الإعلانات يوميًا، و`VIEWER` للمتابعة فقط.
3. فعّل مزامنة الوقت (NTP) على جهاز التشغيل — دقة الأذان تعتمد على ساعته. تظهر لوحة التحكم تحذيرًا إن اختلفت الساعة عن الخادم بأكثر من 30 ثانية.
4. راجع سجل العمليات أسبوعيًا (المستخدمون ← سجل التشغيل ← عمليات المستخدمين).
5. إن فُقد جهاز أو تسرب رمزه: الأجهزة والسماعات ← إلغاء الصلاحية، ثم «إعادة التفعيل برمز جديد» بعد التحقق.
6. احتفظ بنسخة من مجلد `backups/` خارج الخادم.
